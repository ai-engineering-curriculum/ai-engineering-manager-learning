# mod-111-cross-functional-partnership: Cross-Functional Partnership — Governance, Security, Legal, Product, Infra

> Scaffolded by `aicg org execute-plan`. Lecture chapters and exercise content are authored on subsequent autonomous cycles.

**Estimated effort:** 12 hours

## Learning objectives

- Design the release-approval workflow with governance, legal, security, and privacy partners — who signs off on what, which evidence they consume (eval reports, red-team findings, model cards, data-flow diagrams, DPIA inputs), what the end-to-end timeline is for a release
- Operate the interface with the AI Governance family — consume engineered-risk evidence from ai-risk-engineer (level 25), consume release-assurance / audit-trail from ai-evaluation-engineer (level 35), participate in the governance program owned by head-of-ai-governance (level 60) and senior-ai-governance-architect (level 50) without duplicating their scope
- Partner with Product under model uncertainty — the roadmap under non-determinism (mod-103) meets product-shaped roadmaps; disagree-and-commit framing when the model unlocks a feature later than the PRD planned for
- Operate the interface with AI Infra — ai-infra-team-lead (peer manager, level 45, Infra ladder) owns serving / capacity / GPU; this role is the customer. Shared SLOs, shared capacity planning, shared incident path (R17)
- Operate the interface with the AI Workforce family — ai-enablement-lead (level 45, sibling) owns org-wide enablement; this role is a function-level customer; ai-augmented-team-manager (level 40) owns team-level general AI-adoption and is the sibling-below on rituals and 1:1s
- Route legal opinion to counsel, contract execution to procurement / finance, SSO / IAM implementation to IT identity, SOC-side investigation to security operations / DFIR — know what the role does NOT do
