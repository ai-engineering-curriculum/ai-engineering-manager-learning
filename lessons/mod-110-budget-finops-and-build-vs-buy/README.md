# mod-110: Budget, FinOps for Inference, and Build-vs-Buy

> Tenth module of the AI Engineering Manager track. Builds the manager-owned budget-and-economics layer for an AI engineering team: an honest team cost model (model-provider spend broken into input / output / cached / batch / fine-tune, plus labelling data, observability and eval tooling, training compute, infrastructure, and headcount) attributed per feature / per user / per workflow; defensible ROI projections that carry confidence bands and publish the misses alongside the hits; build-vs-buy decisions across the vendor-API / fine-tune / self-host axis that pair with the open-weights portfolio from mod-105 and the Infra partnership from mod-111; a quarterly portfolio-allocation discipline (prototype / productise / wind-down) that refuses to carry zombie initiatives; the FinOps-for-inference levers a manager can own without infra-platform depth (caching rate, batch utilisation, fallback routing, prompt-size discipline, context-window waste); and the two cross-functional partnerships this module centres on — with Finance on cost attribution and with Procurement on enterprise-licence negotiation — with legal opinion deferred to counsel and contract execution deferred to procurement. The inference-platform depth defers to `ai-infra-inference-engineer` and the peer `ai-infra-team-lead` (level 45, Infra ladder); this module teaches the system you require around the platform, not the platform itself.

**Estimated effort:** 14 hours · **Role level:** 45 (AI Engineering family)

## Learning objectives

By the end of this module you should be able to:

- Build the team's cost model across model-provider spend (input / output / cached / batch / fine-tune), labelling data, observability and eval tooling, training compute, infrastructure (serving, retrieval, vector store), and headcount; attribute cost per feature / per user / per workflow honestly, with a defensible allocation key for every shared line item.
- Project ROI on bounded AI initiatives with defensible value-realisation framing — carrying low / mid / high confidence bands, naming the assumptions behind each band, and publishing misses with the reason, not only hits.
- Make build-vs-buy calls across the vendor-API vs. fine-tune vs. self-host axis — scoring each option on cost (now and projected), performance, data posture, lock-in, owned complexity, and reversibility; pairing the call with mod-105's open-weights portfolio decision and mod-111's Infra partnership.
- Run quarterly portfolio allocation across prototype / productise / wind-down — refusing to carry zombie initiatives that consume budget without clearing the productise bar or reaching the wind-down bar; publishing the wind-down decision with the reason, not only the hits.
- Coordinate with Finance on cost-model attribution and variance explanation, and with Procurement on enterprise-licence negotiation — holding the asks a manager owns, deferring contract execution to procurement and legal opinion to counsel.
- Monitor FinOps for inference — caching rate, batch utilisation, fallback routing, prompt-size discipline, context-window waste — as the few levers a manager can own without the inference-platform depth of `ai-infra-inference-engineer`; sequence the FinOps read into the operating cadence from mod-109.

## Where this module fits

- **Depends on `ai-augmented-team-manager` (level 40).** The general management canon on budgeting mechanics, finance literacy at engineering-management altitude, and classical build-vs-buy framing is this module's prerequisite, not its content. This module specialises it to the AI engineering surface, where the cost structure is dominated by non-linear provider-pricing with input / output / cached / batch / fine-tune splits and where build-vs-buy carries a third axis (fine-tune) that classical SaaS build-vs-buy did not.
- **Builds on mod-101 (role ladder and operating contract).** The deferrals this module names — to Finance, Procurement, Counsel, the Infra ladder, the staff-plus ICs — are the contracts mod-101 draws.
- **Pairs with mod-103 (roadmapping non-deterministic work).** The ROI projection (chapter 03) reads against the confidence-banded planning mod-103 teaches; the portfolio-allocation discipline (chapter 05) is the operational expression of mod-103's roadmap discipline.
- **Pairs with mod-104 (eval-driven SDLC and release gates).** The cost model (chapter 02) names the observability and eval-tooling line; the ROI projection (chapter 03) cites eval evidence as a value-realisation input; the wind-down criterion (chapter 05) reads partly against the eval-threshold miss mod-104 defines.
- **Pairs tightly with mod-105 (vendor and model portfolio).** The build-vs-buy call (chapter 04) is the AI-engineering-specific instance of the broader build-vs-buy frame — mod-105 covers the open-weights / self-host side at portfolio depth; this module composes it with the cost model and ROI projection. The portfolio inventory (mod-105 chapter 02) and the self-host memo (mod-105 chapter 06) are inputs to this module's build-vs-buy matrix.
- **Pairs with mod-107 (AI incident response).** The FinOps fallback-routing lever (chapter 06) reads against the fallback plan mod-107 and mod-105 chapter 04 teach; the cost-of-downtime input to the ROI projection reads against incident evidence.
- **Pairs with mod-108 (performance management and growth).** The cost model's headcount line reads against the growth-plan surface mod-108 teaches; the portfolio-allocation wind-down decision (chapter 05) has a people side mod-108 covers.
- **Pairs with mod-109 (team shape and operating cadence).** The team-shape decision (mod-109 chapter 02) and the IC AI-assist stack commission (mod-109 chapter 05) are budget line items this module teaches the manager to defend. The FinOps read (chapter 06) is a beat on the operating cadence mod-109 designs.
- **Pairs with mod-111 (cross-functional partnership).** The Finance and Procurement partnerships (chapter 07) are two of the cross-functional surfaces mod-111 covers at depth. The Infra partnership behind the self-host build-vs-buy (chapter 04) is another.
- **Pairs with mod-112 (executive communication).** The ROI projection (chapter 03), the quarterly portfolio allocation (chapter 05), and the FinOps read (chapter 06) feed the executive-level read-outs mod-112 teaches the manager to compose.
- **Defers down to `ai-infra-inference-engineer` and the peer `ai-infra-team-lead` (level 45, Infra ladder).** Chapter 06 is explicit: the manager monitors five levers at commissioning depth; the inference-platform depth — serving stack tuning, GPU capacity, batching strategy, autoscaling, KV-cache implementation — is the Infra ladder's. The manager reads the dashboard; the Infra engineer ships the platform under it.
- **Routes out to Finance (cost-model attribution, variance explanation), Procurement (contract execution, renewal mechanics), and Counsel (legal opinion on clauses).** The manager owns the asks and the escalations; the three external partners own the mechanics. Chapter 07 is specific about the boundaries.
